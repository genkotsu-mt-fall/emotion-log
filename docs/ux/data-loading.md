# 時間軸データ読み込み仕様案

- 版: 0.1.0
- 状態: Experimental
- 作成日: 2026-07-25

## 1. 目的

ページ番号ではなく時間範囲を基準として、長期間の感情ログを連続的に探索できるようにする。

利用者が時間軸をパンした際、必要なログを先読みし、既に取得したログを失わず再利用する。

## 2. 範囲の定義

### `visibleRange`

現在画面に表示している時間範囲。

### `loadedIntervals`

クライアントが取得済み、取得中、または取得失敗した時間区間の集合。

一つの`loadedRange`だけで管理すると、途中に取得失敗区間や未取得区間がある場合を表現しにくいため、複数区間として管理する。

### `prefetchRange`

現在の表示範囲に隣接し、次に利用者が移動する可能性を考慮して先読みする時間範囲。

## 3. 初期表示

「最新10件」だけでは時間間隔が一定にならず、「直近7日」だけでは記録が少ない場合に空白が大きくなる。

MVPでは、件数と期間を組み合わせた適応方式を検証する。

初期候補:

- 目標ログ件数: 15件
- 最小表示期間: 24時間
- 最大表示期間: 30日
- 表示終点: 原則として最新ログまたは現在日時

手順:

1. 最新ログを含む一定件数を取得する
2. 取得した最古・最新ログの時間差を求める
3. 最小表示期間未満なら最小期間まで広げる
4. 最大表示期間を超えるなら最大期間へ制限する
5. 実際のログ間隔は変えず、時間軸上の位置を維持する

数値はプロトタイプと実データで見直す。

## 4. 基本API要求

時間範囲を指定してログを取得できること。

例:

```http
GET /emotion-logs?from=<inclusive>&to=<exclusive>
```

境界は重複や欠落を防ぐため、原則として次を候補とする。

```text
from <= feltAt < to
```

レスポンスは、取得対象範囲と前後データの有無を返せることが望ましい。

```json
{
  "items": [],
  "range": {
    "from": "2026-07-01T00:00:00Z",
    "to": "2026-07-08T00:00:00Z"
  },
  "hasEarlier": true,
  "hasLater": false
}
```

## 5. 先読みの開始条件

表示範囲が取得済み区間の端へ近づいた場合、隣接期間を取得する。

初期候補:

- 左端から、表示幅の20%以内へ到達したら過去側を先読み
- 右端から、表示幅の20%以内へ到達したら未来側を先読み

先読み期間の初期候補は、現在の表示幅と同じ長さとする。

例:

```text
visibleRange: 7日
過去側先読み: 追加で7日
未来側先読み: 追加で7日
```

高速パン時には、現在位置から大きく離れた不要リクエストを中断できることが望ましい。

## 6. 一期間のデータが多い場合

時間範囲内のログ数が上限を超える場合、カーソル方式で分割取得する。

安定した並び順:

```text
ORDER BY feltAt ASC, id ASC
```

カーソルには、少なくとも`feltAt`と一意な識別子の組を含める。

例:

```http
GET /emotion-logs
  ?from=<inclusive>
  &to=<exclusive>
  &limit=200
  &cursor=<opaque>
```

同一時刻に複数ログが存在しても、欠落や重複が起きないことを要求する。

## 7. クライアント側の保持

ログはIDをキーとして保持する。

```text
logsById: Map<LogId, EmotionLog>
```

取得状態は時間区間ごとに保持する。

```text
interval:
  from
  to
  status: idle | loading | loaded | error
```

新しいレスポンスを受け取った場合:

- IDで統合する
- 同じログを重複表示しない
- 更新版が返った場合は新しい内容へ置換する
- 取得済み区間を統合できる場合はまとめる
- 未取得の隙間を失わない

## 8. リクエスト競合

高速なパンでは、古いリクエストが後から返る可能性がある。

要求:

- 不要なリクエストを中断できる
- 同一範囲の重複リクエストをまとめる
- レスポンス返却順によって表示位置を変更しない
- ログをIDで統合する
- 取得状態を区間単位で更新する
- 古いレスポンスで新しい内容を上書きしない

## 9. 読み込み中と失敗時

- 表示済みのログは残す
- パン操作を全面的に停止しない
- 読み込み対象側に状態を表示する
- 失敗区間だけを再試行できる
- 再試行しても同じログを重複表示しない

## 10. ログ作成・編集・削除との同期

### 作成

- 成功したログをキャッシュへ追加する
- 現在の表示範囲内なら即時表示する
- 保存中状態を表示するかはUI設計で決める
- 保存失敗時は未保存であることを明示する

### 編集

- 同じIDのログを置換する
- `feltAt`変更時は時系列上の位置を再計算する
- 表示範囲外へ移動した場合は現在表示から除く

### 削除

- キャッシュから除去する
- 選択中なら詳細表示を閉じる
- 取得済み区間の状態は維持する

## 11. 拡大・縮小

MVPでは自由なピンチズームより、時間軸のパンと追加読み込みを優先する。

初期候補:

- 1日
- 1週間
- 1か月
- 最新へ戻る
- 日付指定で移動

自由なズームは、パン、重なり、追加取得、タッチ操作が安定した後に再検討する。

## 12. 受け入れ条件案

- 表示範囲の端へ近づくと隣接期間を取得する
- 読み込み中も表示済み範囲を操作できる
- 同じログを複数回取得しても一度だけ表示する
- 同一時刻の複数ログを欠落させない
- 通信失敗時も表示済みログを維持する
- 失敗区間だけを再試行できる
- 高速パン後に古いレスポンスで表示が巻き戻らない
- 作成、編集、削除が時系列表示へ反映される
