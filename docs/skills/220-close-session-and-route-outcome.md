# 220: セッションを閉じ、成果物を振り分ける

## 目的

一議題セッションを正式に閉じ、承認済み結論または未決定状態から必要成果物を決定する。

## 入力

- セッション台帳
- ユーザーが承認した結論または保留状態
- 現在の作業項目
- 関連文書

## 手順

1. `020-single-agenda-session.md`の終了形式でまとめる
2. 未承認提案を結論から除外する
3. `030-outcome-routing-policy.md`を全項目について実行する
4. 新しい独立判断がある場合、元作業の復帰情報を作る
5. リポジトリ変更仕様を列挙する
6. 変更がある場合、`230-create-application-instruction.md`を組み立て規約として同じ応答内で完成済みinstructionまで作る
7. instruction適用後のstateを`pending.application_instruction.status: applied`として定義する
8. 変更がない場合、`250-advance-or-resume-work.md`へ渡す

## 技術判断の扱い

- 未決定で継続追跡が必要: OQを作成・更新し、そのOQを次の作業候補にする
- 技術判断が承認済みでADR条件を満たす: ADR作成をルーティングする
- ADRに加えて要件やロードマップが変わる: 同じinstructionへ含める
- ユーザーに「ADRにするか」を質問しない。判定理由を説明し、異議がある場合だけ修正する

## 出力

- セッションまとめ
- 成果物ルーティング表
- 作成・更新・削除候補
- state遷移案
- instructionの要否

ユーザーに別途`230`を選ばせない。リポジトリ変更が必要なら、同じ応答内で`230`の規約に従った完成済みinstructionを提示する。
