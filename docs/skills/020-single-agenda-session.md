# 020: 一議題セッション規約

## 原則

一回の議論セッションでは、一つの独立した判断だけを扱う。

最小議題とは、他の判断と切り離して次のいずれかへ到達できる疑問文である。

- `Decided`
- `Deferred`
- `Research needed`
- `Blocked`
- `No change`
- `Unresolved`

## 議題の分割基準

次のいずれかが異なるなら、別議題とする。

- 採否を個別に決められる
- 決定期限が異なる
- 影響する文書が異なる
- 調査方法が異なる
- 結論を後から独立して変更できる
- ADRとして別々に置き換えられる

「認証方式を決める」ではなく、例えば次へ分ける。

- MVPの基本認証にメールアドレスとパスワードを採用するか
- MVPで外部IDプロバイダーを提供するか
- メールアドレス確認を必須にするか

## セッション開始

ChatGPTは関連文書を読み、候補を列挙してもよいが、今回扱うのは一件だけにする。

開始時に示すもの:

1. 現在の作業対象
2. 今回の最小議題
3. この議題を今扱う理由
4. 今回扱わない隣接議題
5. 最初の質問一つ

## セッション中

- 一度に質問するのは一つだけ
- 事実、前提、提案、ユーザー承認を区別する
- 新しい独立議題を発見しても横道に入らず、候補として保留する
- ChatGPTの推奨をユーザー決定として扱わない
- 必要な一次情報がない場合は`Research needed`候補とする

## セッション台帳

会話中は次を区別する。

| 区分 | 意味 |
|---|---|
| Confirmed facts | リポジトリや検証結果から確認できる事実 |
| Assumptions | 現時点の仮定 |
| User decisions | ユーザーが明示的に承認した結論 |
| Suggestions | ChatGPTの提案で未承認のもの |
| Deferred items | 今回決めない独立議題 |
| Required evidence | 判断前に必要な調査や検証 |

## セッション終了

ユーザーが結論を承認した、保留を選んだ、調査へ送った、または明示的に終了した時だけ閉じる。

終了時に次を出す。

```yaml
agenda: <一つの疑問文>
result: Decided | Deferred | Research needed | Blocked | No change | Unresolved
decision: null | <承認済み結論>
rationale: <承認済み理由と確認済み事実>
out_of_scope:
  - <今回決めなかったこと>
follow_ups:
  - <独立した後続議題>
```

その後、`030-outcome-routing-policy.md`に従って成果物を判定する。セッション内で直接ファイルを書き換えたことにしない。
