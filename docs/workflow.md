# AIDDの進め方

## 基本の流れ

```text
次に何をする？
  ↓
ChatGPTがリポジトリから作業対象を一つ選ぶ
  ↓
ユーザーとChatGPTで普通に議論する
  ↓
複数の指摘をまとめて成果物全体へ反映する
  ↓
ユーザーが「これで決定」と明示する
  ↓
ChatGPTがCopilot向けinstructionを一つ作る
  ↓
GitHub Copilot WebがブランチとPull Requestを作る
  ↓
ChatGPTがPull Requestをレビューする
  ↓
人間が承認してマージする
  ↓
次に何をする？
```

## 大事な区別

### 一つずつにするもの

次に選ぶ作業対象。

例:

- MVP全体計画
- 一つの要件
- 一つのADR
- 一つのロードマップ
- 一つのタスク
- 一つのPull Request

### 一つずつにしないもの

選んだ作業対象に対するユーザーの指摘。

一度に5件の指摘があれば、ChatGPTは5件すべてを整理し、成果物全体へまとめて反映する。一件ずつ別の議論やinstructionに分けない。

## ユーザーが使う言葉

### 次の作業を始める

```text
リポジトリを確認して、次に何をすればいい？
```

### 複数の指摘をする

通常のチャットとして、箇条書きでも文章でもまとめて伝える。

### 議論を閉じる

```text
この内容で決定。Copilot向け指示書を作って。
```

### 途中保存する

```text
中断して、現在地を保存する指示書を作って。
```

### 実行結果を確認する

```text
このPull Requestを、元の指示書と照合してレビューして。
```

## 成果物の扱い

ADR、要件、UX、OQ、ロードマップ、タスク、CHANGELOGは、ユーザーが別々のワークフローを選ばない。

議論を閉じたとき、ChatGPTが必要な成果物を判断し、同じCopilot向けinstructionへまとめる。
