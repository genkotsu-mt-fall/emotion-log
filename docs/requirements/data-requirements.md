# データ要件

- 版: 0.1.0
- 状態: Draft
- 作成日: 2026-07-25

## 1. User

MVPでは、感情ログの所有者を識別し、自分のログだけへアクセスできることを目的とする。

主な項目:

| 項目 | 必須 | 説明 |
|---|---:|---|
| `id` | 必須 | システム内部の一意な識別子 |
| `loginIdentifier` | 必須 | ログインに使用する識別情報。具体形式は別途決定 |
| `createdAt` | 必須 | アカウント作成日時 |
| `updatedAt` | 必須 | アカウント更新日時 |

## 2. EmotionLog

| 項目 | 必須 | 制約・説明 |
|---|---:|---|
| `id` | 必須 | 一意な識別子 |
| `authorId` | 必須 | ログ所有者 |
| `moodValue` | 必須 | 0〜100の整数 |
| `emoji` | 必須 | 見た目上1字の絵文字 |
| `body` | 任意 | 0〜1000文字 |
| `feltAt` | 必須 | その感情を感じていた日時 |
| `createdAt` | 必須 | システムへ登録した日時 |
| `updatedAt` | 必須 | 最終更新日時 |

## 3. ログ成立条件

最小の有効なログは次で構成する。

- `moodValue`
- `emoji`

本文はなくてもよい。

感情日時の入力が省略された場合、保存処理で`createdAt`と同じ日時を`feltAt`へ設定する。このため、DB上の`feltAt`は必須とする。

## 4. 気分値

- 整数のみ
- 最小値は0
- 最大値は100
- 本人にとってのプラス・マイナス方向を表す
- 利用者間で客観的に比較可能な共通尺度とはみなさない
- 平均、順位、優劣の表示には使用しない

## 5. 絵文字

- 利用者が自由入力する
- 感情カテゴリごとの固定候補だけに制限しない
- 見た目上1字に相当するUnicode書記素クラスタを1つ許可する
- 単純な文字列長だけで検証しない
- 絵文字として扱う範囲と検証方法は、技術選定後に実装方針を決める

## 6. 本文

- 任意
- 空文字または未設定を許可する
- 最大1000文字
- 1000文字は暫定値
- 記録後に追加、編集、削除できる
- UIでは短文を基本とするが、複数段落を許可する
- 改行を保持する
- HTMLを直接保存するか、プレーンテキストとして保存するかは別途決定する
- 初期候補はプレーンテキストとする

## 7. 日時

### `feltAt`

その感情を感じていた日時。利用者が過去日時を指定できる。

### `createdAt`

ログがシステムへ作成された日時。システムが設定し、通常は利用者が変更しない。

### `updatedAt`

最終更新日時。システムが更新する。

### 保存ルール

```text
入力にfeltAtがある
  → 入力値をfeltAtへ保存

入力にfeltAtがない
  → createdAtと同じ日時をfeltAtへ保存
```

内部保存時のタイムゾーン方針は技術設計で決定する。表示時には利用者のローカル時間として理解できることを要求する。

## 8. 同一時刻のログ

同じ`feltAt`を持つ複数ログを禁止しない。

理由:

- 短時間に複数の感情を記録したい可能性がある
- 過去日時を後から入力した場合に衝突する可能性がある
- システム都合で利用者の記録意図を制限しない

並び順を安定させるため、時系列取得では`feltAt`に加えて`id`など一意な値を使用する。

## 9. 公開範囲に関する将来要件

MVPではすべてのログを所有者だけが閲覧できる。

将来は、次の軸を分離して設計する。

### 閲覧対象

- 所有者のみ
- 選択したユーザー
- 選択したグループ
- フォロワー
- サービス内の全利用者
- 未ログインを含むWeb全体

### 公開期間

- 期限なし
- 指定日時から
- 指定日時まで
- 指定期間のみ

「限定公開」は正式な内部状態名として使用せず、閲覧対象と公開期間の組み合わせで表現する。
