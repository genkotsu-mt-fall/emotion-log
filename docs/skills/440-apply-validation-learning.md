# 440: 検証学習を次の成果物へ接続する

## 目的

閉じた検証議題を、バグ、UX改善、要件変更、技術判断、仮説更新、次期ロードマップへ分類する。

## ルーティング例

- 明確な不具合: タスク
- 既存UXの意味変更: 変更記録、UX、CHANGELOG、タスク
- 未確定な利用要求: OQまたは追加調査
- 継続的な技術制約: ADR候補
- 仮説の支持・反証: `docs/product/hypotheses.md`
- 新しい成果のまとまり: MVP後ロードマップ候補

## 出力

- 事実
- 解釈
- 仮説への影響
- 成果物ルーティング
- 統合instruction
- 次の作業と復帰先

一つの観察から必要な成果物をすべて更新するが、独立した別観察を同じinstructionへ混ぜない。
