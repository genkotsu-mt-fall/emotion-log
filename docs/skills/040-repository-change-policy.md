# 040: リポジトリ変更と検証の共通方針

## 原則

ChatGPTとの議論結果と、リポジトリへ適用済みの変更を区別する。

```text
議論を閉じる
→ 成果物をルーティングする
→ 統合instructionを作る
→ CodexまたはGitHub Copilotが適用する
→ ChatGPTが差分を検証する
→ 次工程へ進む
```

## 統合instruction

一つのセッション結論に由来する作成、更新、削除を一つへまとめる。

最低限含めるもの:

- 目的
- 根拠となるセッション結論
- 基準ブランチと対象範囲
- 作成ファイル
- 更新ファイル
- 削除ファイル
- 各ファイルの完成条件
- 変更してはいけない範囲
- 文書間の整合性条件
- 実行する検査
- 完了報告形式
- 適用後の`docs/state.md`

## 適用担当

- 文書の一括変更、定型的実装、テスト、CI修正: Codex向き
- UIの目視調整、デバッグ、技術スパイク、人間主導の局所修正: GitHub Copilot + VSCode向き
- 同じブランチで同時並行に変更しない

## レビュー

適用後はinstructionと実差分を照合する。

判定:

- `Accepted`
- `Accepted after fixes`
- `Rejected`
- `Manual verification required`

確認項目:

- 指定した全ファイルが処理された
- 指定外の意味変更がない
- ADR、OQ、変更記録、正本文書、ロードマップ、タスクが整合する
- CHANGELOGが実変更と一致する
- stateが実際の次工程を示す
- 参照リンクと採番に問題がない

## 人間承認境界

ChatGPTや実装AIは、次を自動確定しない。

- ユーザーのプロダクト判断
- ADRの最終採用
- タスクの`Done`
- 変更記録の`Applied`
- PRの最終承認とマージ
- 本番リリース可否
