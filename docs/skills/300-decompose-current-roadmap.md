# 300: 現在のロードマップをタスクへ分解する

## 使用条件

- 現在ロードマップの目的、対象、成果物、前提、完了条件にBlockerがない
- ユーザーがタスク分解開始を承認している

## 目的

ロードマップを、CodexまたはGitHub Copilotの一回の作業とレビューで扱えるタスクへ分解する。

## 分解原則

- 調査、設計、実装、検証、文書更新を必要に応じて分ける
- 一つのタスクに独立した複数成果を詰めない
- 各タスクに目的、対象、対象外、依存、成果物、完了条件、検証方法を持たせる
- 未決定の技術判断をタスク内で勝手に決めさせない
- リリースに必要なCI、マイグレーション、監視、ロールバック、運用文書を漏らさない

## 成果物

- `docs/tasks/RRR-TTT-<name>.md`
- タスク順序と依存関係
- 最初の未ブロックタスク
- ロードマップとstate更新
- 統合instruction

すべてのタスクは初期状態を`Draft`とする。分解直後に実装指示を作らない。
