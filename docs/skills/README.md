# ChatGPTワークフロー

このフォルダは、MVP計画から本番リリース、リリース後検証までを、ユーザーが成果物種別を選ばず進めるためのスキルを置く。

## 通常の入口

通常は`000-next-action.md`だけを指定する。

```text
リポジトリのmainブランチを基準にしてください。
`docs/skills/000-next-action.md`を読み、その手順に厳密に従ってください。
現在地を確認し、次に必要な一工程だけを選んで実行してください。
議論では一つの最小議題だけを扱い、先の工程へ進まないでください。
```

同じ会話で現在地が維持されている場合、ユーザーは「次に何すればいい？」だけでよい。

## ユーザーに見える流れ

```text
次に何すればいい？
→ ChatGPTが現在地を読む
→ 一つの工程または最小議題を進める
→ 必要なら統合instructionを作る
→ CodexまたはCopilotが反映・実装する
→ ChatGPTが結果をレビューする
→ 次に何すればいい？
```

ADR、変更記録、OQ、要件、UX、CHANGELOGは別々のユーザーワークフローではない。セッション終了時にChatGPTが必要性を判定する成果物である。

## 構成

| 範囲 | 役割 |
|---|---|
| `000`〜`040` | オーケストレーション、状態、セッション、成果物振り分け、変更規約 |
| `100`〜`130` | MVPリリースまでのロードマップセット策定 |
| `200`〜`250` | 現在作業の開始、議論、終了、反映、レビュー、復帰 |
| `300`〜`360` | タスク分解、実装、レビュー、完了 |
| `400`〜`440` | リリースとリリース後検証 |
| `internal/` | ADR、変更記録、OQ、正本文書、CHANGELOG、stateの生成品質規約 |

## 重要原則

- 一回の議論で一つの独立判断だけを扱う
- 技術判断が必要でも、ユーザーにADRルートを選ばせない
- 大きな別議題は現在作業を中断し、復帰先をstateへ保持する
- 一つの結論に必要な成果物は一つの統合instructionへまとめる
- 議論結果と適用済み差分を区別し、反映後に必ずレビューする
- `Done`、`Applied`、リリース可否は人間承認なしに確定しない
